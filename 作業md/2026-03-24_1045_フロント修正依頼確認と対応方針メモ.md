### 起きたインシデントと対応
#### 1. PowerShell 由来の文字化け表示と、実ファイル破損の切り分けミス
- 事象:
  - PowerShell の表示上の文字化けを扱う流れの中で、index.html を誤ったエンコーディング前提で再保存してしまい、実ファイルを壊した。
- 原因:
  - 「表示上の文字化け」と「実体の文字コード」を分離して扱うべきところで、保存処理に進めてしまった。
- 対応:
  - git restore --source=HEAD --worktree -- index.html で正常状態へ復旧した。
  - 以後、PowerShell 表示の文字化けは表示問題として扱い、保存時は UTF-8 を明示するよう切り替えた。
- 再発防止:
  - 日本語ファイルに対して Get-Content 経由の再保存を安易に行わない。
  - 文字列置換時は UTF-8 明示の読み書きか、apply_patch を優先する。

#### 2. apply_patch の継続失敗
- 事象:
  - apply_patch が windows sandbox: setup refresh failed で失敗するケースが複数回発生した。
- 原因:
  - ツール側の失敗であり、パッチ内容そのものではないケースがあった。
- 対応:
  - 最小差分のときは UTF-8 を保った PowerShell / .NET の文字列置換で代替した。
- 再発防止:
  - まず apply_patch を試し、失敗が再現する場合のみ UTF-8 明示の代替手段へ切り替える。

#### 3. Basic Information の HTML / CSS 反映ズレ
- 事象:
  - index.html と css/top-page.css、および src/main/resources/static/css/top-page.css の反映内容が一時的にずれた。
- 原因:
  - HTML 側追加後、CSS 追加が片系統だけに入るタイミングがあった。
- 対応:
  - 実ファイルを見ながら、静的側と Spring Boot 側の両方へ同内容を反映し直した。
- 再発防止:
  - index.html に直接反映した UI は、対応する css/*.css と src/main/resources/static/css/*.css の両方を同時確認する。
