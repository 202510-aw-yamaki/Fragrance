## 10. インシデント記録と対応方針

### 10-1. 2026-03-26 チェックリスト運用逸脱
- 事象:
  - ユーザー確認が必要な判断項目を、事前確認なしで確定文へ書き換えたうえで完了チェックした。
- 問題点:
  - 元の論点が消える。
  - ユーザー合意の有無が追跡できなくなる。
  - 後任者が「仕様確定済み」と誤認しやすくなる。
- 対応:
  - `作業md/2026-03-26_1230_重大インシデント_チェックリスト運用逸脱と再発防止.md` を作成し、再発防止ルールを明文化した。
  - 以後は、判断事項を含むチェック項目は元文言を残し、必要なら直下注記で結果を書く方式に統一した。
- 後任者向け指示:
  - チェック済み項目でも、文言が実装都合で書き換わっていないか確認すること。
  - 判断を含む項目は、ユーザー合意ログが確認できるまで完了扱いにしないこと。

### 10-2. 文字化けの誤判定と実ファイル破損
- 事象:
  - PowerShell の表示文字化けを実ファイル破損と誤認し、日本語ファイルを誤った前提で再保存して壊したことがある。
- 問題点:
  - 表示上の問題と、実体の文字コード問題を混同すると、不要な破壊的編集が起きる。
- 対応:
  - PowerShell 表示だけでは破損判定しない。
  - 日本語ファイルは UTF-8 を明示して扱う。
  - 最小差分編集を優先し、安易な全面再保存をしない。
- 後任者向け指示:
  - 「表示だけが崩れている」のか「ファイル内容が壊れている」のかを切り分けてから編集すること。
  - 日本語ファイルに対する一括置換や再保存は慎重に行うこと。

### 10-3. レイアウト修正中の意図しない文言変更
- 事象:
  - ヘッダー調整中に、ナビ文言が日本語から英語へ一時的に置き換わり、作業報告で十分に明示されていなかった。
- 問題点:
  - レイアウト修正と文言変更は別種の変更であり、同列に扱うと確認漏れが起きる。
- 対応:
  - 文言変更、見出し変更、`alt` 変更、`aria-label` 変更は、レイアウト変更と分けて扱うルールにした。
- 後任者向け指示:
  - 見た目調整でも、ユーザーに見える文字列を変えた時点で重要変更として扱うこと。
  - 特にヘッダー、CTA、見出し、`alt`、`aria-label` は変更有無を別で報告すること。

### 10-4. 構造差分を見ずに局所補正したことによる手戻り
- 事象:
  - ヘッダーやロゴ位置ずれを、構造差分確認前に局所 CSS やピクセル補正で直そうとして手戻りが発生した。
- 問題点:
  - 根本原因が `header-inner`、共通 CSS、ページ個別 CSS の責務差分にある場合、局所補正では安定しない。
- 対応:
  - まず共通構造とページ個別上書きの差分を確認する。
  - `translateY()` などの見た目合わせは最後の手段とする。
- 後任者向け指示:
  - 「表示されていない」のか「押し出されて見えない」のかを分けて考えること。
  - HTML 反映有無と CSS 圧迫は別問題として扱うこと。
