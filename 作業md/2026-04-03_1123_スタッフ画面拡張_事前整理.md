# 2026-04-03 11:23 スタッフ画面拡張 事前整理
## 1. 目的
- スタッフ画面に対して、来店種別管理、担当管理、半年未来店抽出、論理削除、優良顧客フラグ運用を追加する前提を整理する。
- 画面内で完結させる運用を優先しつつ、判断を含む仕様を先に固定する。
- 既存の一覧ソート、ページング、スクロール挙動も合わせて改善する。

## 2. 今回の対象機能
- 来店種別の追加・削除・表示管理
- 担当の追加・削除・表示管理
- 半年以上来店がない候補の抽出
- 抽出候補の論理削除
- 優良顧客フラグの設定・解除
- ソート後のスクロール位置保持
- 一覧表内でのヘッダー追従

## 3. 半年未来店抽出の方針
- 一覧画面に `半年未来店一覧` ボタンを設置する。
- 押下時に「半年以上来店がない」かつ「優良顧客フラグ未設定」の予約だけを抽出する。
- 抽出結果はモーダルで表示する。
- モーダル内では以下を可能にする。
  - 詳細確認画面を別タブで開く
  - 優良顧客フラグを付与する
  - チェックした予約を論理削除する
- 即時削除ではなく、抽出確認後に削除判断させる運用にする。

## 4. 優良顧客フラグの扱い
- フラグ名は `優良顧客フラグ` とする。
- 詳細確認画面に常設し、設定・解除を行えるようにする。
- フラグ付き予約は半年未来店抽出の対象外とする。
- 抽出モーダル側にもフラグ付与導線を置く。

## 5. 削除の扱い
- 半年未来店候補の削除はまず論理削除で対応する。
- 論理削除後の物理削除は別運用とし、現段階では画面機能に含めない。
- 来店種別と担当の削除も論理削除とする。
- 来店種別・担当を論理削除しても、既存予約の表示上は名称を残す。
- 一覧や新規選択肢では、論理削除済み項目は選択対象から外す。

## 6. 来店種別と担当の管理 UI
- 来店種別と担当の追加 UI は、各管理欄の入力 + 追加ボタンで表現する。
- 削除ボタンは各項目ごとに設置する。
- 削除時は `本当に削除しますか？` の確認を必須とする。
- 削除後も既存表データの表示値は維持する。

## 7. 担当のデータ設計
- 来店種別は既存 `visit_types` を使う。
- 担当は文字列直書き運用ではなく、担当マスタを新設する。
- `reservation_slots.instructor_name` の既存表示は後方互換のため残しつつ、今後の管理は担当マスタを正とする。
- 一覧表示は担当マスタ名を優先し、必要時のみ既存文字列へフォールバックする。

## 8. ソート・スクロール方針
- ソートボタン押下時のスクロール位置を保持する。
- 一覧をスクロールしても表ヘッダーが表内で追従するようにする。
- 対象パラメータは `visitType` / `instructor` / `sort` / `dir` / `page` / `size` を維持する。

## 9. 現時点で確定した仕様
- 保護フラグ名称は `優良顧客フラグ`
- 半年未来店候補はモーダル表示
- モーダル内で `詳細確認画面へ移動 / フラグ付与 / 削除` を選択可能
- 詳細確認画面は別タブで開く
- 来店種別・担当の追加/削除ボタンは各管理欄に配置
- 来店種別・担当の削除は論理削除
- 論理削除後も既存表データの表示値は残す
- 担当は担当マスタ新設で対応する
