# 2026-03-17 14:35 DB未設定起動対応とバックエンド土台追加

## 1. 対象
- Spring Boot バックエンド実装の継続
- DB 未設定でも画面確認と API 確認を続けられるようにする対応

## 2. 背景
- 2026-03-17 時点で Java 21 / Maven Wrapper で ./mvnw.cmd spring-boot:run 実行は可能になった
- ただし mybatis-spring-boot-starter と DataSource 自動構成が有効なため、pplication.yml に DB 接続設定がない状態では起動時に停止した
- エラー要旨:
  - Failed to configure a DataSource: 'url' attribute is not specified

## 3. 実施内容
- Java ソースの BOM によるコンパイルエラーを解消した
  - src 配下の .java / .xml / .yml / .sql を UTF-8 without BOM に正規化
- 予約系バックエンド土台を追加した
  - src/main/java/com/fregrance/app/model
  - src/main/java/com/fregrance/app/mapper
  - src/main/resources/mapper
  - src/main/resources/schema.sql
  - src/main/resources/data.sql
- ReservationService に DB 利用時の永続化ルートを追加した
- ReservationSlotService に Mapper 利用時の取得ルートと、未接続時のモックフォールバックを整理した
- FregranceApplication で、当面は DB 未設定でも起動確認できるように以下の自動構成を除外した
  - DataSourceAutoConfiguration
  - MybatisAutoConfiguration

## 4. 現時点の方針
- 今は「DB 未設定でも起動して画面確認ができること」を優先する
- MyBatis / DB 接続の本実装は、接続先や運用方針が固まった段階で再度有効化する
- その際は自動構成除外を見直し、DB 接続設定とあわせて戻す

## 5. 未解決事項
- ReservationService / ReservationSlotService で追加した DB 利用ルートは、現在は自動構成除外中のため未使用
- pplication.yml に実 DB 接続設定はまだ入っていない
- QuestionnaireResult 系の Model / Mapper は未着手
- スタッフ画面、認証、一覧・詳細画面は未着手

## 6. 次アクション
- ./mvnw.cmd spring-boot:run を再実行して、DB 未設定でもアプリが起動するか確認する
- http://localhost:8080/api/health と http://localhost:8080/reservation.html を確認する
- 起動が通ったら、次はアンケート結果保持まわりのバックエンド土台に進む
