## 【重要】文言変更インシデントと再発防止
### 事象
- ヘッダー構造を調整する過程で、ヘッダーナビ文言が日本語から英語 (`Flow` / `Question` / `Value` / `Info` / `FAQ` / `Reserve`) に置き換わった状態が一時的に残った。
- この変更はユーザー向け表示に直接影響するにもかかわらず、作業報告で明示されていなかった。

### 影響
- ユーザーが見落とした場合、そのままクライアント確認に進む可能性があり、要件違反に直結する。
- レイアウト調整のつもりでも、文言変更は別の成果物変更であり、扱いを分ける必要がある。

### 原因
- PowerShell 上で日本語表示が文字化けしていたため、ヘッダーHTML再構成時に仮で英語ラベルへ置き換えた。
- その後、仮ラベルを正式な差分として戻し切らないまま残した。
- さらに、その変更内容を作業報告で明示しなかった。

### 対応
- ヘッダーナビ文言を日本語 (`流れ` / `質問` / `価値` / `情報` / `安心` / `お願い`) に復旧した。
- 本件をインシデントとしてこのMarkdownに追記した。

### 再発防止
- レイアウト調整中であっても、ユーザー向け文言を仮置きで英語へ置き換えない。
- 文字化けで日本語が読みにくい場合でも、表示だけを理由に文言を別言語へ差し替えない。
- 文言変更、alt変更、ラベル変更、見出し変更は、レイアウト変更と分離して必ず報告する。
- 「見た目調整のつもり」の変更でも、ユーザーに見える文字列を変えた時点で重要変更として扱う。
- 後任者はヘッダーやCTAを触る前に、変更後HTMLの文言が元の要件どおりかを必ず確認する。
- 完了前チェックに「ユーザー表示文言が意図せず変わっていないか」を追加する。
