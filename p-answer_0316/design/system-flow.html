レイヤー構成の説明 必須

フロントエンドは既存のページ構成を踏襲しつつ、画面間で `sessionStorage` に逃がしていた状態を API と DB に置き換える。公開ページは Controller で画面表示と API 受付を分け、Service で分岐判定、5軸スコア算出、予約確定、重複枠チェックを担当する。

Repository は回答、香りプロフィール、予約、予約枠、スタッフ情報を永続化する。これにより、現在はブラウザ内で完結している体験を、来店前情報として店舗側が参照できる運用システムへ接続できる。

2 リクエスト処理フロー

一覧表示の処理フロー 必須
予約枠一覧表示

1. ユーザーが reservation.html を開く
2. フロントが選択中の日付を付けて GET /api/reservation-slots?date=yyyy-mm-dd を呼ぶ
3. ReservationController が日付形式を検証する
4. ReservationSlotService が営業日と公開可否を確認する
5. ReservationSlotRepository が reservation_slots から空き枠を取得する
6. Controller が JSON を返す
7. フロントがモーダルまたは一覧UIに反映する
登録処理のフロー 必須
予約登録処理

1. ユーザーがアンケート完了後に予約情報を入力する
2. フロントが必須入力をチェックし POST /api/reservations を送信する
3. ReservationController が ReservationForm を受領する
4. QuestionnaireValidator / ReservationValidator が入力妥当性を検証する
5. FragranceProfileService が回答からルート種別と5軸値を確定する
6. ReservationService が予約枠の重複を確認する
7. ReservationService が Reservation / QuestionnaireAnswer / FragranceProfile を組み立てる
8. 各 Repository がトランザクション内で保存する
9. 予約確認番号を生成してレスポンスを返す
10. 完了画面が予約内容を表示する

3 画面遷移フロー

全体の画面遷移図 必須
[公開導線]
/index
  -> /questionnaire/step1
  -> /questionnaire/step2?route={routeType}
  -> /fragrance-graph
  -> /reservation
  -> /reservation/complete/{reservationCode}

[管理導線]
/staff/login
  -> /staff/reservations
  -> /staff/reservations/{id}
  -> /staff/reservations/{id}/memo

補足
- 公開導線は離脱を減らすため匿名アクセス
- 管理導線は認証必須
- routeType は Bloom / Air / Deep / Exploratory を使用

5 認証・認可フロー

Spring Security の認証フロー 必須

公開ページは `permitAll` とし、ログインを要求しない。スタッフ画面は Spring Security で `STAFF` と `ADMIN` を扱い、予約閲覧は `STAFF` 以上、予約枠管理やスタッフ管理は `ADMIN` のみに制限する。

1. /staff/login にアクセス
2. UsernamePasswordAuthenticationFilter が認証
3. 成功時に SecurityContext へ権限格納
4. /staff/** は STAFF, ADMIN を許可
5. /admin/** は ADMIN のみ許可
6. 認証失敗時は login 画面へ戻す
