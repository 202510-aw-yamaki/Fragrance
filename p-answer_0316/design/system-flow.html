レイヤー構成の説明 必須

公開画面は Controller でテンプレート返却と REST API を分けて扱い、Service で分岐判定、5軸スコア算出、予約確定、重複枠チェックを担当する。DB 入出力は MyBatis Mapper に集約し、SQL を明示的に管理する。

入力値検証は Request DTO / Form に対するバリデーションで行い、例外は `@RestControllerAdvice` で統一する。これにより、現在のプロトタイプ導線を実運用向けの API と管理画面へ安全に接続できる。

2 リクエスト処理フロー

一覧表示の処理フロー 必須
予約枠一覧表示

1. ユーザーが reservation 画面を開く
2. フロントが GET /api/reservation-slots?date=yyyy-mm-dd を呼ぶ
3. ReservationController が日付形式を検証する
4. ReservationSlotService が営業日と公開可否を確認する
5. ReservationSlotMapper が reservation_slots を検索する
6. Controller が ReservationSlotResponse の JSON を返す
7. フロントがモーダルまたは一覧UIに反映する
登録処理のフロー 必須
予約登録処理

1. ユーザーが回答・予約情報を入力する
2. フロントが POST /api/reservations を送信する
3. ReservationController が ReservationForm を受領する
4. Validation と Service が入力妥当性を確認する
5. FragranceProfileService が回答から routeType と 5軸値を算出する
6. ReservationService が重複予約を確認する
7. ReservationService が ReservationModel / QuestionnaireAnswerModel / FragranceProfileModel を組み立てる
8. 各 Mapper がトランザクション内で INSERT / UPDATE を実行する
9. 予約確認番号を生成し、ReservationResponse を返す
10. フロントが完了画面に遷移する

3 画面遷移フロー

全体の画面遷移図 必須
[公開導線]
/index
  -> /questionnaire/step1
  -> /questionnaire/step2?route={routeType}
  -> /fragrance-graph
  -> /reservation
  -> /reservation/complete/{reservationCode}

[管理導線]
/staff/login
  -> /staff/reservations
  -> /staff/reservations/{id}
  -> /staff/reservations/{id}/memo

補足
- 公開導線は匿名アクセス
- 管理導線は Spring Security で認証必須
- routeType は Bloom / Air / Deep / Exploratory を使用

5 認証・認可フロー

Spring Security の認証フロー 必須

公開ページは `permitAll` とし、ログインを要求しない。スタッフ画面と管理APIは Spring Security で `STAFF` / `ADMIN` を扱い、権限ごとにアクセスを分離する。

1. /staff/login にアクセス
2. UsernamePasswordAuthenticationFilter が認証
3. 成功時に SecurityContext へ権限格納
4. /staff/** は STAFF, ADMIN を許可
5. /admin/** は ADMIN のみ許可
6. 認証失敗時は login 画面または JSON エラーを返す
